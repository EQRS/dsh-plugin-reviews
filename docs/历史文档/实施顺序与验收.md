## 1. 实施顺序

按依赖先后划分六个阶段。每阶段交付对应业务服务、必要迁移、用户页面、管理入口和有意义的验证；完成标准以可执行流程和数据结果为准。后台跟随业务实施，服务器管理员日常不需要操作数据库表。阶段可在开发环境演示，整站 P0 上线须完成全部阶段。

| 阶段 | 实施范围 | 完成标准 |
|---|---|---|
| 1. 基础能力 | 项目与 Linux 构建；共享契约；SQLite 连接、迁移与 Repository；GitHub 登录、本站会话与权限；配置、审计、持久队列及 worker；最小后台入口。 | 空库可初始化；Web 与 worker 独立启动；登录和禁用有效；管理员通过页面修改一项注册配置；任务重启后可恢复，旧执行权不能提交结果。 |
| 2. 插件目录 | GitHub / Awesome 适配与来源合并；仓库及子路径身份；发现、同步、缓存与请求预算；分类、人工覆盖、安装资料核验、纠错；插件列表、详情、搜索及相应后台。 | 相同插件多来源合并；用户可独立提交插件；同步故障保留旧资料，未完成轮次不误撤销来源；可从搜索进入真实详情，核验状态和复制命令符合实际记录。 |
| 3. 单篇评测 | 公共内容与修订、草稿、版本字段；Markdown 与附件接收、图片处理、本地存储；提交检查、人工复核、发布、修改、撤回；个人中心、评测列表与搜索、首页及审核后台。 | 作者从插件页写一篇含图评测，保存、提交、发布、修改、撤回均可演示；改稿期间旧正文保留；搜索和媒体权限随公开状态正确变化；管理员可处理失败或疑难检查。 |
| 4. 整合包 | 包身份、草稿与不可变发布版本；插件清单、DSH 版本、实测声明、可选配置；安装命令展示与复制；列表、详情、历史版本、作者管理及审核。 | 创建包并发布两个版本，各版本清单和配置独立；撤回新版后默认页回到最近仍公开版本；未知版本、未实测和待核实安装资料按规则标示；复制遗漏项清晰提示。 |
| 5. 批量与互动 | Markdown / 图片文件夹导入、逐项确认和集中投稿；公平队列；评测及包版本评论回复；收藏、有帮助、举报、通知、本人事项、后台处理与资料维护。 | 批次中成功、失败和需补充项目独立保留，断网重试不重复创建；其他作者可获得处理机会；评论关联正确对象，通知不重复；日常内容和数据管理通过网站完成。 |
| 6. 部署与整体验收 | Compose、代理和正式回调；运行观察、备份、维护、迁移、升级回退、恢复；四条 P0 端到端流程与目标 Linux 验证。 | 测试部署可以按文档建立、停止、重启及恢复；全部关键验收通过并有记录；实际启用的外部服务完成真实接入验证；未配置能力如实显示。 |

阶段 1 建立最小可用接口，后续按业务需要扩展，避免先实现没有调用者的通用平台。迁移按依赖成组提交，真实外键、联合约束及循环建立顺序从首次引入对应表时生效；不能先关闭约束运行再计划补回。Web、worker 与后台共用服务，不分别复制发布、权限或配置逻辑。

每阶段完成后按结果修正代码和实施记录；不把任务已登记、按钮已出现或页面用了样例数据认定为业务完成。具体 UI 可后续调整，错误、恢复入口、版本归属、响应式与基本可访问性仍属于功能验收。

## 2. 四条端到端验收

沿用需求第 28 节，每条同时覆盖匿名、普通用户、作者和管理员的适用权限，以及故障提示、数据保留和恢复方式。

| 流程 | 完整操作与判定 |
|---|---|
| 浏览 | 目录搜索筛选 → 插件详情 → 评测正文／包版本 → 安装资料；关键词、筛选、分页和版本定位正确。只返回当前可公开内容，未知或待核实资料清楚显示。 |
| 创作 | GitHub 登录 → 从插件页写评测／创建整合包 → 保存与恢复 → 提交检查 → 发布 → 修改 → 撤回；同时执行含缺图的批量导入、补充及重试。快照不可改、草稿私有、旧公开内容在新稿通过前保留。 |
| 互动 | 评论与回复 → 修改／删除 → 收藏与取消 → 有帮助与取消 → 举报 → 通知定位与已读；包版本讨论不串联，自己回复自己不通知，隐藏或撤回目标不泄露正文和附件。 |
| 管理 | 统一待办 → 人工决定／补充／复核 → 资料纠错与覆盖 → 同步与恢复 → 用户及管理员管理 → 配置、任务、存储、备份与审计查看；动作真实生效，合法历史可追溯，至少保留一名正常管理员。 |

## 3. 关键一致性与故障验收

使用独立测试数据库、附件目录和明确标识的测试账户。测试默认不调用正式服务、不修改正式数据；外部故障通过受控测试适配器注入。适配器测试与真实提供商验证分别记录，不能互相冒充。

| 范围 | 必须制造的条件 | 必须观察到的结果 |
|---|---|---|
| 数据约束 | 缺失具体子类型、跨文章修订、跨包版本评论、跨批次输入、缺失附件引用、回滚。 | 非法关系由实际生产迁移拒绝；合法循环关系提交成功；业务写入和投影一起回滚。 |
| 保存与提交 | 两个页面保存同一草稿；同一请求重发；重复提交和晚到响应。 | 冲突不覆盖新稿；成功请求重复返回正确回执，不重复创建修订、任务或事件。 |
| 权限变化 | 禁用作者后恢复；审核期间撤回或隐藏；两个管理员同时改变最后一名管理员。 | 旧待发布任务仍失去资格；决定基于正确快照和当前权限；至少一名正常管理员约束在并发下成立。 |
| 任务恢复 | 两个 worker 竞争；领取后强制终止；到期重新领取；原执行者迟到写回；请求超时。 | 只有有效执行权可结束尝试或提交成功；进度和回执保留；自动重试遵守次数与冷却，不能无限重跑。 |
| 检查发布 | 规则通过／需补充，内容疑难，提供商超时、未配置或图片能力不足。 | 转换符合既定状态机；故障不自动放行、不认定违规；人工复核可用，发布版本和通知不重复。 |
| 目录同步 | 分页未完成、截断输入、部分条目失败、304 缓存复用、来源撤回、覆盖存在、上游限流与重启。 | 保留完整输入和完成证明；不误判来源消失；人工覆盖不被冲掉；持久额度、冷却和重复合并有效。 |
| 安装资料 | 无安装说明、多个候选、目标版本不可获取、固定提交子路径错误、核验到期。 | 不臆造安装信息；只复制当前符合既定核验规则的命令，未生成项和原因明确；不在站点运行插件。 |
| 文件与批次 | 传输中断、换文件重选、超限、处理失败、重复领取、页面关闭。 | 完整接收结果复用，输入摘要不匹配时拒绝错误复用；逐项恢复不重复生成草稿；执行权过期不能完成旧传输。 |
| 媒体与切源 | 私有／公开／撤回附件访问；副本缺失或摘要错误；迁移中断；启用后新源故障。 | 未授权读取被拒绝；不完整副本不能启用；稳定 URL 不变，可从正确本地保底读取同一内容。 |
| 搜索与缓存 | 中文双字／三字、组合筛选；发布、修改、隐藏、撤回及事务失败；已有缓存。 | 查询命中规则一致；私有或不再公开内容不因旧索引／缓存泄露；更新与回滚保持一致。 |
| 批量公平性 | 一个作者积压大量投稿时，另一作者提交；部分项目永久失败。 | 按已确认调度规则给其他作者处理机会；失败不阻塞其他项目，不新增每小时篇数限制。 |
| 互动与通知 | 同一事件重放、重复投票／收藏、删除有回复评论、版本切换、通知目标受限。 | 不重复计数或通知；删除保留合法回复；包版本归属正确；受限通知不泄露内容。 |
| 配置与管理 | 越界参数、跨参数冲突、配置更新时任务仍在运行、越权后台请求。 | 非法配置不生效；运行尝试使用原快照，新尝试采用新配置；审计完整，越权被拒绝。 |
| 部署与恢复 | 磁盘不足、正常／强制停机、迁移失败、镜像回退、数据库及媒体恢复。 | 不报告虚假成功、不切内存库、不自动清理历史；恢复匹配数据库与文件，并核验可登录、可读取、可继续处理。 |

备份恢复必须至少演练一次：创建含图片、公开／私有内容、历史版本和未完成任务的恢复点；在另一个隔离目录或测试部署恢复；核验数据库完整性、外键、文件摘要及稳定媒体路径、管理员访问和任务重新调度。原环境仍保留，不通过覆盖唯一数据副本来演练。

## 4. 验证方式与记录

契约和状态转换使用有意义的单元验证；涉及外键、事务、唯一条件、并发和 FTS 的验证运行真实 better-sqlite3 与实际迁移。worker 恢复和媒体迁移使用进程／服务集成验证；四条完整流程用浏览器验收，并覆盖手机布局、键盘操作、错误和冲突提示。外部适配器使用固定输入验证解析与故障，再对正式启用的提供商执行受控真实接入检查。

在目标 Linux、固定应用镜像和记录的资源条件下测试，不复制 Windows 检查结果作为上线结论。记录目录及文章规模、任务积压、并发读写、上传图片数量、响应延迟、锁等待、内存和磁盘占用；具体容量与响应目标依据预期流量另定，不把未测的吞吐数写成承诺。

每项验收记录至少包含：编号、需求／架构引用、应用镜像与迁移版本、环境、测试数据、操作步骤、期望结果、实际结果、证据、通过／失败／待验证、遗留问题。缺陷修正后复验受影响流程；失败项不能仅通过改写期望结果关闭。

目前已有的九组 SQLite 机制检查和八项 Windows 依赖检查仅作为选型证据；最终业务 schema、任务并发、浏览器、Linux 容器和恢复流程仍须按本计划验证。本文所有新增验收项目初始为待验证，不标记为通过。

## 5. P0 完成与上线条件

六阶段和需求第 28 节四条流程全部完成。权限、发布、执行权、媒体访问、历史保留、关键数据一致性和恢复能力没有未解决的阻断缺陷；上线候选与测试镜像一致，正式目录、配置和凭据核对完成，升级前恢复点可用。

真实 GitHub 登录、目录读取和发布检查接入按实际启用能力验收。服务商以后填写不阻塞本地开发；审核未配置时按既定待处理／人工复核流程运行，不能标称自动审核已完成。默认本地存储可作为首版部署，未启用 S3 时其适配器可做受控验证，真实服务商检查标为未启用，不影响本地完整恢复验收。

预览页面、测试适配器和生成示例不充当生产功能。独立备份未配置时不能宣称已有灾难恢复；上线记录如实说明部署能力、待接入项和已测容量。具体 UI 后续可继续完善。

DSH 一键导入／自动安装、整合包标签、插件评分、富文本编辑器、视频托管、读者旧评测正文差异和邮件推送继续留后续，不因本阶段追加到 P0。

本类别确认后，五类架构收尾进入实施阶段。下一项工作是阶段 1 的项目初始化及基础能力；本轮仅整理文档，未开始应用编码或上线。
