# 验收纪律：怎么判断"真的做完了"

本项目用 Agent Teams 并行施工。**汇报不等于事实**，下面是主控实际执行的复核动作，以及它们各自抓到了什么。

## 1. 为什么不能只读汇报

并行施工最容易出的三种假象：

| 假象 | 长什么样 | 真实案例（本项目已发生） |
|---|---|---|
| **恒真测试** | 测试全绿，但断言永远成立 | 见 §3 的变异验证 |
| **半成品被当交付** | 报告说完成，文件正在被编辑或语法错误 | 同一时刻另一个桶的文件处于编辑中，typecheck 报语法错 |
| **破坏性实验残留** | 变异测试改了源码，还原静默失败 | GI 自述：`-ErrorAction SilentlyContinue` 让还原静默失败，两处破坏代码留在文件里 |
| **规格笔误外溢** | 主控给的导入路径写错，实现照抄 | `@server/modules/tasks` 应为 `@/server/modules/tasks`，导致 TS2307 |

## 2. 主控实际做的复核动作（逐条）

1. **自己跑一遍，不信汇报里的数字**
   `npx vitest run <该桶的测试>` —— 比对实际 passed/failed 数与汇报是否一致。
   例：GI 报 61 passed，实跑 61 passed（后来 62）✅

2. **抽查最高风险声明**（挑"如果错了最致命"的那条，去源码里看，不去看测试）
   - 抽查「明文凭证不入库」→ 读 `identity/service.ts`，确认是 `newOpaqueToken()` → `digestText(token)`，且查询按摘要进行 ✅
   - 抽查「按 (repository_id, plugin_path) 幂等」→ 读 `catalog/service.ts`，确认先查后插 ✅

3. **扫残留**
   - 全仓 `grep` 变异标记（`&& false` / `padEnd(64)` / 临时破坏注释 等）
   - 全仓找 `*.bak` / `*mutation*` 文件
   - 本项目实测：抓到过一次 `tasks/service.ts.mutation-bak`，但确认是 GT 正在进行的变异实验，随后其自行清理干净 ✅

4. **区分"我的错"和"他的错"**
   发现 `@server/modules/tasks` 导入失败时，先回查自己写的任务描述 —— 确认是主控笔误，于是**不改队友的文件**，而是通知队友修，并说明根源在规格。这保证写范围不被越权破坏。

5. **整仓门禁由主控统一跑，不派给各桶**
   各桶只对自己的文件类型干净负责；`tsc --noEmit` 与全量 `vitest` 在合并前由主控统一执行，避免并行中互相看到半成品而误判。

## 3. 变异验证（anti-tautology）——本项目采用的标准

**做法**：故意破坏一处实现，确认对应用例**变红**，再还原、复跑确认变绿。

已固化为脚本：`scripts/verify-tests-bite.mjs`（删掉盖楼触发器 → 约束测试必须失败 → 还原 → 必须通过）。

各桶自报的变异矩阵：

| 桶 | 破坏点 | 期望变红 |
|---|---|---|
| GI | 去掉幂等查询 | catalog 2 failed |
| GI | 短路 `dsh.bundle` 检查 | catalog 1 failed |
| GI | `token_digest` 改存明文 | identity 8 failed |
| GI | 重复回调改 always insert | identity 3 failed |
| GI | 去掉 `revoked_at` 检查 | identity 2 failed |
| GF | 堆栈塞进响应体 | 自检变红 |
| GF | 未知异常原样回传 message | 自检变红 |
| GF | 未登记 code 不兜底 | 自检变红 |
| GF | `request_id` 放行换行 | 自检变红 |

**关键教训（GI 自述，值得抄下来）**：
> 破坏性实验的还原必须**逐条回读验证**，不能信 exit code。
> 我用 `-ErrorAction SilentlyContinue` 还原时静默失败了，破坏代码留在文件里；
> 因为没有相信脚本回执、而是回读源码 grep 校验，才抓出来。

## 4. 结论口径

一条工作包只有在下列全部成立时才被主控标为完成：

- [ ] 主控**自己**跑过该桶测试，数字与汇报一致
- [ ] 至少抽查 1 条最高风险声明，在**源码**里坐实（不只看测试）
- [ ] 该桶零残留（无 `.bak`、无变异标记）
- [ ] 该桶自己的文件类型干净
- [ ] 汇报里明确列出了「未做／不确定」，且主控逐条答复了边界
