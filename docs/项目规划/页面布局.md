# 第三类收尾：页面布局与交互呈现

状态：页面分区与入口已确认；对应架构第 108 节。用户要求具体 UI 以后调整，以下颜色、尺寸与预览作为可调整初稿。依据已确认 P0 需求和架构第 1—107 节，将已有业务落实到页面、区块和交互。示意预览见 [页面布局预览](页面布局预览.html)，使用虚构示例，只演示排布与切换，不连接后台。

## 1. 总体方向

采用中文资料社区布局：搜索和分类入口明确，列表便于扫描，文章适合长时间阅读，版本和来源清晰。参考 [MC百科首页](https://www.mcmod.cn/) 的检索、分类、资料与文章分区；参考 [Awesome DSH Plugin](https://awesome-dsh-plugin.com/zh/) 的插件目录信息组织。本站页面与功能范围以既定需求为准，以下布局是本站提案，不将参考站点的功能自动纳入 P0。

首版以浅色为基础，白色内容面板、浅灰背景、蓝色主要操作，弱化阴影及装饰。来源、实测、核验和可访问状态使用不同文字标签，不将“站点评测”“已审核”“安装资料已核验”画成同一种保证。用户头像、插件图标和评测封面沿用真实来源及占位规则。

公共页面最大内容宽度建议 1200px；阅读正文建议 720—800px；详情辅栏 260—300px。桌面正文与辅栏之间留 24px，手机页边距 16px。基础正文 16px、行高约 1.7，辅助文字不小于 14px；中文使用系统无衬线字体，代码使用等宽字体，无需强依赖远程字体服务。

颜色、尺寸、间距、字号和断点统一为设计 token，基础定义见 [界面基础定义](界面基础定义-MASTER.md)；分类、模板、可用动作、业务状态文案及参数读取既定契约。视觉 token 通过主题定义维护，首版不据此增加任意页面搭建器或后台 CSS 编辑器。

## 2. 导航与页面入口

桌面顶部：站名／首页链接、插件、评测、整合包；右侧为通知与账户。未登录时显示“GitHub 登录”，已登录时显示头像及账户菜单，管理员菜单增加后台入口。通知显示本人未读数；没有消息时不展示错误告警样式。

全站导航中的“插件／评测／整合包”进入各自列表。搜索在首页与各列表的主体区域提供，输入框明确说明搜索范围；文章阅读页不再出现含义不明的第二个文章搜索框。首版不增加同时混搜三类内容的全站结果页。

| 页面组 | 建议网站路径 | 入口与归属 |
|---|---|---|
| 首页 | `/` | 搜索插件、分类、最新评测、近期更新插件。 |
| 插件目录／详情 | `/plugins`、`/plugins/{plugin_id}` | 目录提供提交插件，详情进入安装资料、评测、收藏和纠错。 |
| 全站评测／文章 | `/reviews`、`/reviews/{review_id}` | 列表搜索公开文章；详情只读当前公开正文。 |
| 整合包列表／默认详情 | `/packs`、`/packs/{pack_id}` | 一包一项，默认最近仍公开的版本。 |
| 指定整合包版本 | `/packs/{pack_id}/releases/{release_id}` | 固定版本链接，评论只属于该版本。 |
| 首次资料确认／个人设置 | `/onboarding`、`/me/settings` | 昵称、头像和 GitHub 主页公开选择，可跳过首次确认。 |
| 我的评测／整合包 | `/me/reviews`、`/me/packs` | 文章／包归组，管理草稿、提交与历史。 |
| 草稿编辑 | `/me/drafts/{draft_id}` | 根据类型使用评测／包编辑表单，访问核验本人归属。 |
| 导入与批量投稿 | `/me/batches`、`/me/batches/{batch_id}` | 上传接收、逐项确认、草稿、投稿结果与恢复。 |
| 收藏／通知／我的事项 | `/me/favorites`、`/me/notifications`、`/me/cases` | 收藏分两类，通知本人可见，事项按真实类型进入详情。 |
| 后台 | `/admin` 及注册业务子页 | 待办、目录、字典、用户、配置、任务、存储、备份与审计。 |

以上是网站页面路径提案，不替换已定义的 `/api/...` 业务接口。评论定位使用对象页及评论标识；明确类型的事项详情、提交详情和后台子页在对应列表进入，不通过任意表名生成路径。浏览详情、打开编辑或管理页均不自动提交、发布、复制新版本或标记所有通知已读。

## 3. 首页：三块内容，入口优先

```text
站名           插件   评测   整合包              通知 / 账户
───────────────────────────────────────────────────────
找 DSH 插件        [插件名称、仓库、作者或用途……] [搜索]
用途分类：全部 / 已启用分类……                     更多插件
───────────────────────────────────────────────────────
最新评测（主体约 2/3）              近期更新插件（约 1/3）
标题、来源、对应插件与版本          图标、名称、简介、分类
作者、时间、可选封面                有效更新时间、公开评测数
全部评测                           全部插件
───────────────────────────────────────────────────────
站点说明及来源链接
```

首页搜索只搜索插件，结果进入 `/plugins` 并保留关键词；分类进入该分类目录。最新评测默认 6 条、近期更新插件默认 12 条，取当前配置。站点／社区评测在同一时间列表中展示来源标签，不将站点来源自动置顶。最近更新取有效资料变更时间，不取每日重新检查时间。

手机按搜索、分类、最新评测、近期更新插件单列排列；分类很多时有展开全部入口，不让所有分类挤成横向不可见菜单。首页暂不增设热门榜、轮播广告、用户排行榜或人工推荐运营位。

## 4. 插件目录与全站评测列表

桌面采用“标题及操作 → 搜索 → 筛选／排序 → 结果与分页”。插件目录左侧可放用途分类，右侧为结果；评测采用可选封面＋文字的紧凑条目。手机筛选收进可展开区域，页面持续显示当前条件及清除入口。

| 列表 | 搜索与筛选 | 条目信息与排序 |
|---|---|---|
| 插件 | 名称、仓库、作者、简介；用途分类；全部／已有评测／暂无评测 | 图标、名称、作者、简介、用途、有效更新时间、公开评测数及可用状态。无关键词默认最近更新，可切公开评测最多；关键词优先相关度。 |
| 全站评测 | 标题、当前公开正文、对应插件名；全部／站点／社区；插件用途分类 | 封面或插件图标占位、标题、来源、关联插件、插件及 DSH 版本、作者、时间。无关键词按发布时间，有关键词按相关度。 |
| 整合包 | 当前默认版本的名称与用途 | 名称、用途、作者、插件数量、当前公开版本。无关键词按默认版本发布时间，有关键词按相关度；没有用途标签筛选。 |

插件列表的“提交插件”打开专用链接表单：输入仓库／子目录链接 → 检查 → 已收录直接进入详情，未收录成功后进入新详情，需要补充分支或子路径时保留原输入并提供对应项。排队、限流和检查故障在原表单显示；不把“正在检查”显示成“正在安装”。

所有条件、排序和页码进入 URL，改变条件回第一页；显示真实总数及已采用分页参数。缺少图片使用占位，不把空封面当成缺少评测。筛选无结果显示清除条件；目录真正为空时提供提交插件入口，不能两者共用误导文案。

## 5. 插件详情：资料与评测同页可达

顶部摘要：插件图标、名称、仓库作者、简介、用途、当前上游状态及资料时间。主要操作为“写评测”“收藏”“源码”，纠错作为“反馈资料错误”次要入口。README 作者与评测作者分别展示。

桌面主栏：插件介绍／README → 本插件评测列表；辅栏：安装资料、来源和核验时间、仓库／插件子路径。顶部区块导航可直达“介绍”“评测”“安装资料”，使用页内锚点，关键资料不藏在默认不打开的标签页中。README 很长时可折叠，但必须提供明确展开按钮；评测有独立区块与直接跳转入口。

安装区分别展示核验状态、实际固定目标、命令和上游说明链接。仅当前匹配且有效的成功核验生成复制命令；未知、过期、待核实或失效显示原因及来源入口，旧成功依据标明原时间。未执行安装的资料不得标“安装成功”。仓库归档、临时不可访问及同步故障分别说明，不清空最后有效资料。

插件内评测提供来源与被测插件版本筛选，包括明确未知；默认发布时间从新到旧，与全站评测指向同一文章。不重复提供一套不同语义的文章搜索。无评测显示“暂无评测”和“写第一篇评测”，不显示插件零分。

手机顺序为摘要及主要操作、安装资料摘要、插件介绍、评测列表、来源详情；源说明可展开。写评测及评测跳转在顶部可见，长 README 不阻断到达评测区。操作按钮自动换行，不使用遮挡正文的浮动安装条。

## 6. 评测文章：正文主栏，版本明确

文章头部依次为关联插件链接、标题、站点／社区来源、插件与 DSH 被测版本、作者、首次发布时间及公开更新时间。正文使用适合阅读的宽度；文章封面可选，不强制增加巨幅封面。未知版本保持“未知”，版本标签不是兼容承诺。

桌面辅栏提供对应插件摘要、返回插件页、已有结构化版本信息，以及根据 Markdown 标题生成的文章目录；正文没有标题时不生成空目录。手机辅栏内容移到文章头部／文末，目录可展开。

正文后放“有帮助”、分享链接、举报及评论。当前作者另有进入私有管理页的编辑入口，不在公开正文页直接覆盖文章。待审修改仍显示旧公开正文，公开页不展示私有处理进度；本人在个人中心查看“已公开，修改待检查”。

文章撤回或隐藏时公开页只显示允许告知的状态、返回插件／列表入口，正文、封面、历史修订与评论不继续显示。作者可经本人管理入口查看有权访问的内容及复核，不将公开 URL 变成登录后即可任意读私有历史的入口。

## 7. 整合包详情与版本切换

头部：名称、用途、作者、包内发布序号、DSH 版本、作者实测声明、实际发布时间、收藏及分享。紧邻头部显示当前所看版本，并提供仍公开版本的切换列表；指定版本链接始终保留明确 release_id。

主栏按顺序展示插件清单、组合说明、可选配置及使用步骤、实测任务与结果、该版本评论。清单每项保留顺序、插件身份、作用、显示版本、固定安装目标及核验状态；插件链接读取当前目录，历史展示资料不被新资料直接替换。

安装资料按清单顺序提供逐条复制和“复制全部可用命令”。有遗漏时先明确列出不能生成命令的项目及原因，再由用户确认复制可用部分；配置单独复制。按钮不命名为“一键安装”“导入 DSH”，不显示首版尚不存在的执行入口。

已实测是作者声明，旁边有实际任务与结果；未实测照常展示，不以审核通过代替实测。配置模板不含真实密码或 Key，展示适用 DSH 版本及需本地填写的占位符。

版本切换同时切换清单、配置、实测与评论，并取消旧版本尚未完成的读取／输入确认，不混用跨版本数据。若评论框已有未提交文字，提示保留后再切换，后续仍必须针对原版本或用户重新确认的目标提交。指定旧版已撤回时显示原版状态与默认入口，不静默替换成另一版本；默认入口回退时标明已选最近仍公开版本。

手机清单条目改为纵向卡片，不要求横向滚动才能看到版本及核验状态；代码块可局部横向滚动，复制按钮始终有可见标签。

## 8. 编辑投稿与批量导入

评测编辑器顶部显示当前插件、标题、插件与 DSH 版本、可选封面。主体为 Markdown 编辑／预览；桌面可以左右分栏，手机切换“编辑／预览”，切换不丢输入和光标上下文。工具栏有标题、加粗、列表、插图、插入参考模板、导入文件。模板是可选插入，已有正文时明确插入位置，不自动替换全文。

整合包编辑器复用正文与草稿能力，并增加名称／用途／DSH 版本、插件选择器与有序条目、可选配置、适用版本及实测表单。选择“已实测”展开任务与结果必填项；新版本必须重新确认实测。条目重排同时提供上移／下移按钮，不能只支持拖拽。未收录插件复用指定链接检查，检查完成后再加入清单。

动作区始终区分“保存草稿”和“提交检查”。显示保存中、已保存时间、保存失败或离线本地暂存；仅本地暂存不标成服务端已保存。提交前提示将使用哪份已保存内容，生成固定快照后显示检查结果入口，不能因作者继续编辑就改变已提交正文。

字段错误在对应控件旁展示，多个错误同时提供顶部可聚焦错误摘要及跳转；例如“请选择插件或先保存为草稿”“插件版本请填写或选未知”。附件逐图显示传输、处理、失败及允许重试，上传完成不等于处理通过。版本未知、负面评价、未按模板写作和未实测不作为表单违规。

保存冲突保留当前编辑内容，展示服务器已变化并提供读取当前已保存内容的明确选择，不无条件覆盖本地。网络故障不清空输入；重新登录后必须核验还是原作者，不能把另一个账户登录视为原草稿权限恢复。

批量流程使用独立页面：选择 MD／文件夹及图片 → 接收进度 → 待确认清单 → 预览／逐篇修正 → 保存草稿 → 勾选齐全项提交。列表列为文件名／标题、对应插件、图片问题、草稿状态、投稿阶段及操作；支持已确认的多篇统一选插件，不新增批量撤回或批量删除。

顶部汇总完成、待确认和失败数量，详情逐项显示真实进度，不按时间估算百分比。关闭页面后可从个人中心继续；需要重选文件的项目提示实际缺少文件，已完整输入不重复上传。处理失败与等待补传分开；任务重试不等于重新投稿，作者批量提交后不要求按小时分批回来。

## 9. 评论、轻量表单与通知

评测和包版本使用同一评论组件。顶部是评论数量／已确认排序及输入框；讨论组先显示顶层评论、至多当前配置条数回复、展开更多回复和独立分页。回复框注明回复谁，并持续展示其所属文章／包版本，手机不无限缩进。

评论有自己已允许的编辑／删除，其他用户有回复／举报；正文修改后待检查时仍显示当前公开修订，本人通过对应状态查看修改进度。删除／隐藏／目标不可公开按第 78—79 节处理，保留群组关系需要的占位信息，不能用历史正文填占位。排队提示只说明已提交检查，不伪装成公开发布。

举报、资料纠错、复核及补充使用共用表单框架，目标由服务端明确返回。字段少时用对话框，较长材料进入独立事项详情；确认时有目标摘要、原因／说明、允许的链接及正确动作标签。必填理由不因点击按钮而省略，关闭前有输入时允许保留，处理后返回真实事项详情。

通知页按建立时间列本人提醒、未读状态和目标入口，提供既定单条／全部已读操作。进入目标不自动把所有通知已读；已不可公开内容显示允许的状态，不展示缓存正文。管理反馈只显示本人允许查看的结论和材料要求，明确“查看处理”“补充材料”或“申请复核”等实际允许入口。

## 10. 个人中心：对象、草稿、提交各有位置

桌面左侧导航，右侧内容；手机为栏目选择或可展开导航。栏目为我的评测、我的整合包、导入与投稿任务、收藏、通知、我的事项、个人设置。收藏分插件／整合包两类，事项分举报／纠错／复核并保留各自访问范围。

我的评测一篇一项，同时显示公开状态、最新提交阶段和是否有编辑草稿；例如“已公开 · 修改待检查 · 有未提交编辑”。进入详情再看当前正文、草稿、修订历史及允许动作，不将每次修订当成新文章。

我的整合包一个包一项，详情内分当前默认公开版本、编辑草稿、确定版本及处理记录。尚未发布版本不显示虚构“第 N 版”；旧版撤回与新版待检查分开。历史管理列表分页，正文按点击读取，不能首次加载全量历史。

收藏允许保留不可访问状态项，并提供取消收藏；没有公开包版本时不显示旧版私有名称、配置或缩略图。用户设置只改昵称、头像、GitHub 主页公开选择等允许字段；角色、封禁原因及秘密身份资料不成为普通用户表单控件。

## 11. 后台：统一待办，按业务维护

后台顶部标明管理区域，左侧按工作分组，默认进入待处理事项。桌面列表加详情布局，材料较长进入独立详情；手机按列表→详情顺序，主操作与原因表单仍可完整使用。

| 导航组 | 页面主要内容 |
|---|---|
| 待处理事项 | 人工审核、举报、纠错、复核；待处理／待补充／已处理；目标、原因、时间和实际处理入口。 |
| 插件资料 | 有效值、来源、人工覆盖；修正与恢复同步、指定核验及已有批量导入。 |
| 内容管理 | 文章／包版本／评论的当前公开与控制状态；设置站点评测、隐藏及解除隐藏的正式动作与历史。 |
| 分类与模板 | 分类、映射、参考模板的字典表单、启停、顺序、默认模板及影响说明。 |
| 用户管理 | 角色、账户状态、管理版本和操作历史；至少保留一名正常管理员。 |
| 任务与同步 | 真实队列、目录轮次、逐项结果、预算冷却、故障和有权重试；不将系统任务成功等同于内容已发布。 |
| 存储与备份 | 存储状态、实际副本验证、迁移进度、真实恢复点与独立副本；允许启动及恢复动作，不开放手改文件归属。 |
| 业务设置与审计 | 注册参数分组表单、单位／范围／生效时点、当前配置版本、修改原因和历史；操作按目标查询。 |

待办默认由旧到新，统一列表只汇总已定义需人工处理的真实事项；自动排队不是人工待审。复核接管的提交只进入当前有效事项，不复制两份独立审核入口。

处理详情将确定提交／举报快照、当前公开内容、依据、当事人补充和历次决定分区；用户可见反馈与内部证据分开编辑。底部按当前资格给出通过、需修改、要求补充、隐藏或实际资料修正等动作，必填原因；不是任意状态下拉框。两人处理冲突时刷新新决定并保留未提交说明，不直接覆盖。

配置页不让管理员填 key、外键 ID 或 SQL。存储凭据只展示非秘密引用与健康状态，配置地址迁移调用专门流程；普通设置保存不冒充迁移完成。备份展示数据库快照、必需文件验证及独立副本的不同状态，不用一个绿色“任务成功”掩盖不完整恢复点。

## 12. 响应式、访问受限与交接

建议布局断点：<768px 单列；768—1023px 紧凑布局，可展开辅栏；≥1024px 正文＋辅栏／筛选栏。中间宽度按实际内容是否放得下决定，浏览器放大与长中文标签均不得压住按钮。长代码块局部滚动；图片宽度不超过正文，手机不以桌面宽表格作为唯一读法。

| 情况 | 展示与恢复 |
|---|---|
| 初始加载 | 对应区块骨架／明确加载文字，保留标题与入口位置。 |
| 空结果／首次无数据 | 搜索为空提供改词／清条件；无评测提供写评测；无草稿提供既定创作入口。 |
| 排队／外部冷却 | 显示真实阶段、允许公开的等待原因及下一次查询安排，不承诺具体完成时间。 |
| 查询故障 | 保留最后成功状态并注明暂未更新，按第 104 节退避；不把读失败当成业务失败。 |
| 写入故障／冲突 | 保留输入，显示未成功及正确恢复动作；复用原请求键确认，不生成重复操作。 |
| 未登录／到期 | 公开内容可浏览，写入提示 GitHub 登录；私有数据停止更新并清理过期展示，本地输入按账户隔离。 |
| 禁用／无权访问 | 显示允许告知的状态，停止私有读取及写入，不回显内部管理原因。 |
| 已撤回／隐藏／不存在 | 状态页或统一不存在提示，不返回旧正文、图片、配置；本人管理按独立权限进入。 |

键盘可完成导航、搜索、投稿、图片选择、顺序调整和管理动作；可见焦点不被吸顶栏或操作区遮挡。原生链接负责跳转，按钮负责动作，所有输入有标签；弹窗有明确标题、关闭按钮、焦点管理及回到触发控件。错误有文字说明，状态不只靠颜色，自动进度更新不反复抢焦点。

主要控件点击区域建议至少 44×44 CSS px，紧凑表格也保留足够操作间距。对比度和读屏语义在实现时实测，不能用“已采用蓝色”替代无障碍验证。减少动态效果设置下保留状态反馈但不进行大幅动画；首版没有自动轮播。

本类别确认内容为页面分区、入口、响应式及业务状态呈现。示意预览不代表完整应用，精确视觉 token、所有表单及真实数据状态在实现验收中验证。下一类为依赖选型与 Linux 部署，最后一类为实施顺序和验收；本阶段不发布站点。
