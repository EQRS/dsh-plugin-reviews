# 并行工作包（分发给队友的自包含说明）

本文件是每个队友开工前必读的**工作包规格**。它自包含，不依赖对话历史。

## 0. 项目一句话

DSH Plugin Review（DeepSeek Harness 插件评测网站）的**最小功能切片**：
**登录 → 收录插件 → 写／审／发一篇评测 → 评论**。

完整设计文档在工作区根目录（`idea.md`、`架构设计.md`、`数据库模型.md`、`参数与管理规则.md`、`页面布局.md`）。
但**不要把整包规划当施工顺序表**——那是设计评审意见点名的失败模式。本切片只做上述一条链路。

## 2. 关键不变量（实现必须真的做到，测试必须能证明）

1. **外键真的开着**：连接工厂在事务外执行 `PRAGMA foreign_keys = ON`，启动自检 `PRAGMA foreign_key_check` 干净。
   **禁止 `PRAGMA foreign_keys = OFF`，禁止删外键换取写入顺序。**
2. **延迟配对**：`content_entities.id` = `reviews.id`，同一事务内先插公共实体（带 `review_id = id`）与具体表，让延迟外键在 commit 时验证。不允许"先关约束，回头再补"。
3. **`save_version` 原子条件更新**：`UPDATE content_drafts SET ... WHERE id = ? AND save_version = ?`；影响行数 0 → 抛 `version_conflict`，保留用户输入。
4. **请求去重**：`draft_save_receipts(draft_id, request_key)`、`content_submissions(submitted_by, request_key)`、`operation_records(action_type, operation_key)`。**同键同摘要 → 返回原结果，不重复创建**；**同键不同摘要 → `request_key_reused`**。
5. **提交生成不可变快照**：`review_revisions` 一旦写入就不可 UPDATE（触发器已强制）。
6. **发布资格**：发布事务内重新核验「提交仍是当前最新提交 / 文章未撤回未隐藏 / 修订归属正确」，通过才切 `reviews.published_revision_id` 并写 `content_entities.first_published_at`、`public_updated_at`。
7. **可见性统一解析**：公开 = 存在有效公开修订 **且** `withdrawn_at IS NULL` **且** `hidden_at IS NULL`。**不得**在业务表另存"公开状态"字段。
8. **评论盖楼**：回复时 `root` = 被回复者是顶层则取自身，否则取其 `root_comment_id`；创建后不可改（触发器已强制）。
9. **执行权 CAS**：任务续期、写回、结束都必须校验 `execution_token` **且** `lease_expires_at > now`。旧进程晚到的写回必须被拒绝。
10. **状态机**：提交 `pending→checking→approved→published`；明确缺失 → `needs_changes`；有疑问 → `manual_review`；**外部检查未配置或故障绝不自动放行，也不认定违规**。
11. **时间与 ID**：只用 `platform/time.ts` 的 `nowMs()` 与 `platform/id.ts` 的 `newId()`。

## 3. 测试纪律（最重要的一条）

- 每个测试必须**能在实现被破坏时变红**。
- 禁止恒真断言（例如 `expect(true).toBe(true)`、只断言"返回了对象"）。
- 数据库测试使用**真实临时文件 + 真实迁移**，不用 `:memory:` 冒充。
- 至少每个工作包要有一条"删掉约束/关掉校验就必须失败"的对照测试。
