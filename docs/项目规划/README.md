## 三、效力与维护规则

1. **`idea.md` 是 P0 基线**：`需求初稿` 里的内容不算需求，除非被 `idea.md` 引用。
2. **改了规划就改这里**：不要只在 PR/issue 里口头达成新口径。改完同时做两件事 ——
   * 在 [`决策记录.md`](决策记录.md) 追加一条（日期 / 决策 / 为什么 / 影响面）；
   * 更新 [`差距报告`](../现状-对规划-差距-2026-10-19.md) 对应行的判定与证据。
3. **文档与实物冲突时以实物为准**，并把差异写进差距报告，不要悄悄改文档去迎合代码。
4. 代码注释里引用「架构第 XX 节」「参数 §XX」时，以本目录同名文档为准。

改名为 `docs/项目规划/`。相对链接因此只多了一层目录（同目录内的链接仍然有效）。
