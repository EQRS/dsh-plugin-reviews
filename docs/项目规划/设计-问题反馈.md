# 设计：问题反馈（分类工单）

> 状态：**已确认方向、待实现**（2026-11-02 与主创确认）
> 方案选型：**B（分类工单）+ A（单表落库 + 后台队列 + 站内通知）**
> 关联：`docs/项目规划/设计-精选专栏.md`、`docs/项目规划/设计-AI翻译简介.md`

## 1. 需求与边界

### 1.1 要解决的问题

站点目前只有三套「用户提交 → 后台处理」的通道（举报 / 资料纠错 / 整合包申诉），
**没有「站点功能出问题」的通道**：页面打不开、搜索搜不到、按钮没反应、导入失败、显示错乱——
这些既没有违规内容可举报，也不是某个插件的资料写错了，用户只能去别处喊。

### 1.2 已确认的做法

| 决策 | 结论 |
|---|---|
| 形态 | 分类工单：先选类型（bug / 功能建议 / 内容问题 / 账号问题 / 其他）再填对应字段 |
| 提交门槛 | **必须登录**（不开放匿名）——保证能站内通知，也天然抑制灌水 |
| 图片 | **允许上传截图**（复用现有 media 上传与像素/格式闸） |
| 可见性 | **默认全私有**；另设 `/known-issues` 只读页，只展示管理员挑选公开的条目 |
| 回复 | **站内通知**（登录用户，无需邮件） |

### 1.3 明确不做

- 不做全站浮层式「上下文自动采集」（方案 C 未选）：宁可在表单里自动带上来源页面地址，也不在每页挂采集组件；
- 不做全量公开的社区看板（避免把站点弱点清单公开、避免治理成本）；
- 不做匿名提交、不做邮件/IM 通知、不做工单分派给多个处理人（只有管理员）；
- 不替代现有三套机制：内容违规仍走举报，插件资料错误仍走纠错。

## 2. 与现有机制的边界

| 通道 | 表 | 处理谁 | 入口 |
|---|---|---|---|
| 内容举报 | `reports` | 评测/评论/整合包版本**违规** | 内容详情页「举报」 |
| 插件资料纠错 | `plugin_correction_requests` | 某个插件的**字段写错** | 插件详情页「纠错」 |
| 整合包申诉 | `pack_appeals` | 作者对**下架/拒绝**不服 | 整合包版本页 |
| **问题反馈（本设计）** | `feedback_tickets` | **站点自身**的功能/体验/账号问题 | 页脚与账户菜单「反馈问题」 |

判断口诀：**「站点的错」→ 反馈；「内容的错」→ 举报；「资料的错」→ 纠错；「判决的错」→ 申诉。**
表单首屏就写这句，减少进错通道。

## 3. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 一张票据表 + 一张处理记录表 | 与 `reports` / `corrections` 同构，团队心智负担为零 |
| D2 | 类型字段进主表，不建多张表 | 五种类型的字段差异用「共有字段 + 类型专属段」表达即可 |
| D3 | 状态六态：`open / acknowledged / fixed / duplicate / wontfix / unreproducible` | 没有「无法复现 / 重复」，队列一周就烂 |
| D4 | 处理**必须写理由**，写进处理记录 | 沿用 `reports` / `corrections` 的既有约定 |
| D5 | 提交人只能看自己的票 | 默认私有；公开是管理员主动挑选的结果，不是默认 |
| D6 | 公开页 `known-issues` 用票上的**公开摘要**字段 | 不另建表：票内部私有，公开的是管理员写的对外说明 |
| D7 | 附件用现有 `attachments` + 引用表 + **owner 触发器** | 照抄 `draft_attachment_links` 那套，防越权引用 |
| D8 | 每用户每小时上限走 `rate_limits.feedback_per_hour` | 现有平台级限流，加一个 spec 即可 |
| D9 | 同用户 + 同类型 + 同页面 24h 内去重 | 阻止「狂点提交」；与 `reports` 的唯一索引同思路 |
| D10 | 通知新增 kind `feedback_result` | 处理完投一条，带 `link_url = /feedback/{id}` |
| D11 | 表单自动带「来源页面」但不做浮层 | 只带 URL（去敏感 query）与白名单环境字段，够定位即可 |
| D12 | 关闭开关即回到现状 | 新增设置 `feedback.enabled`，关掉后入口隐藏、接口 404 |
| D13 | 入口不加主导航 | 页脚「反馈问题」+ 账户菜单「反馈问题」+ 内容详情页底部一行（避免导航拥挤） |
| D14 | 不设「修复中」中间态 | 状态只到 `acknowledged`，避免多头状态与用户预期错位（主创 2026-11-02 定） |

## 4. 数据模型（迁移 0036）

### 4.1 `feedback_tickets`

| 字段 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | TEXT PK | UUIDv7 |
| `kind` | TEXT | `bug` / `feature` / `content` / `account` / `other` |
| `title` | TEXT | 1–120 字，去首尾空白后非空 |
| `body` | TEXT | 1–5000 字 |
| `page_url` | TEXT NULL | ≤ 1000；提交页面的站内路径（表单自动带，可改） |
| `page_kind` | TEXT NULL | `plugin` / `review` / `pack` / `search` / `other`；由 `page_url` 前缀推断 |
| `object_id` | TEXT NULL | 关联对象 id（插件/评测/整合包），仅用于后台快速跳转 |
| `context_json` | TEXT NULL | 白名单字段：`ua / screen / lang / tz / ua_platform`；`CHECK (json_valid)` |
| `status` | TEXT | 六态，默认 `open` |
| `visibility` | TEXT | `private` / `public`，默认 `private` |
| `public_summary` | TEXT NULL | ≤ 500；`visibility = public` 时必填，是给站外看的说明 |
| `duplicate_of` | TEXT NULL | 自引用 `feedback_tickets(id)`；`status = duplicate` 时必填 |
| `submitted_by` | TEXT | → `users(id)` RESTRICT（不开放匿名） |
| `created_at` / `updated_at` | INTEGER | ≥ 0 |
| `closed_at` | INTEGER NULL | 终态时写入 |

约束：

- `CHECK (status IN (...))`、`CHECK ((status = 'duplicate') = (duplicate_of IS NOT NULL))`；
- `CHECK ((visibility = 'public') = (public_summary IS NOT NULL))`；
- `CHECK (closed_at IS NULL OR status IN ('fixed','duplicate','wontfix','unreproducible'))`（反向：终态必须有 `closed_at`，用触发器或应用层保证）；
- 索引：`IDX(status, created_at DESC)`（后台队列）、`IDX(submitted_by, created_at DESC)`（我的反馈）、`IDX(visibility, closed_at DESC)`（公开页）。

### 4.2 `feedback_handling_records`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | |
| `ticket_id` | TEXT | → `feedback_tickets(id)` CASCADE |
| `handled_by` | TEXT | → `users(id)` |
| `action` | TEXT | `acknowledge` / `fix` / `duplicate` / `wontfix` / `unreproducible` / `publish`（公开） / `unpublish` |
| `reason` | TEXT | **必填**，1–1000 字 |
| `reply_text` | TEXT NULL | 可选，给提交人的完整回复（写进通知正文） |
| `notified` | INTEGER | 0/1，通知是否已投递（幂等重试用） |
| `created_at` | INTEGER | ≥ 0 |

### 4.3 `feedback_attachment_links`（照抄草稿附件那套）

```
feedback_attachment_links(ticket_id, file_id)  PRIMARY KEY (ticket_id, file_id)
```

- `file_id` → `attachment_files(id)`；`ticket_id` → `feedback_tickets(id)` CASCADE；
- **触发器**：只能引用本人上传的附件（与 `trg_draft_attachment_owner_insert` 同义）；
- 应用层限制：每条最多 3 张（`feedback.max_attachments`），单张走 media 既有像素/格式闸（jpeg/png/webp）。

### 4.4 通知扩展（重建 `notifications`，同 0034 手法）

- `kind` 增 `feedback_result`；
- `link_url` 已存在（0034 加的），存 `/feedback/{id}`；
- CHECK 调整：`feedback_result` 属于「无 comment_id、有 detail、可无 content_entity_id」的一类——与 `moderation_result` / `featured_published` 同组。

### 4.5 设置项（新增 3 项）

| 键 | 默认 | 说明 |
|---|---|---|
| `feedback.enabled` | `true` | 总开关 |
| `rate_limits.feedback_per_hour` | `10` | 每人每小时提交上限 |
| `feedback.max_attachments` | `3` | 每条最多截图数 |

## 5. 状态机

```
                       ┌──────────────┐
        提交 ─────────▶ │     open     │
                       └──────┬───────┘
                    确认(acknowledge)
                              ▼
                       ┌──────────────┐
                       │ acknowledged │
                       └──┬────┬───┬──┘
            修复(fix) ────┘    │   └──── 无法复现(unreproducible)
                              │ 重复(duplicate) → 指向另一票
                          不修(wontfix)

终态：fixed / duplicate / wontfix / unreproducible（写 closed_at）
```

- **不设「修复中」状态**（D14）：用户侧只看到「已提交 / 已确认 / 已修复（或重复、不修、无法复现）」，少一层猜测；
- 只有 `open` / `acknowledged` 可继续流转；终态**不可主动重开**（可由管理员手动改回 `acknowledged` 并记一条处理记录）；
- `duplicate` 必须指向一个存在的票，且**不能自指、不能成环**（应用层校验 + 目标票不能被删）；
- 每次状态变化**必须**写一条 `feedback_handling_records`（含理由），这是审计的唯一来源。

## 6. 页面与入口

| 位置 | 内容 |
|---|---|
| `/feedback` | 提交表单（先选类型，再显示该类型的提示与字段）+ 我的反馈列表（状态、时间、最后回复） |
| `/feedback/{id}` | 我的单条反馈详情（正文、截图、状态流转历史、管理员回复） |
| `/admin/feedback` | 队列：按状态/类型筛选，默认 `open`；显示类型、标题、页面、提交人、时间 |
| `/admin/feedback/{id}` | 处理页：原文 + 上下文 + 截图（可全屏看）+ 操作（确认/修复/重复/不修/无法复现）+ 理由 + 回复文本 + 「公开到已知问题」 |
| `/known-issues` | 只读公开页：只看 `visibility=public` 的条目（标题、公开摘要、状态、修复时间），不显示提交人 |
| 入口 | 页脚「反馈问题」+ 账户菜单「反馈问题」；插件/评测/整合包详情页底部一行「这一页有问题？反馈给站方」（带 `page_url` 预填） |

### 6.1 表单字段（按类型）

| 字段 | bug | 功能建议 | 内容问题 | 账号问题 | 其他 |
|---|---|---|---|---|---|
| 标题 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 详细描述 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 复现步骤 | ✅（多行，可空但强烈建议） | — | — | — | — |
| 页面地址 | 自动带，可改 | 自动带 | 自动带 | — | 自动带 |
| 截图 | ✅ | 可选 | 可选 | 可选 | 可选 |
| 期望结果 | ✅（可空） | ✅（建议里必填） | — | — | — |

### 6.2 关于「上下文」的边界（重要）

不做全站浮层，但表单提交时会带：

- **来源页面**：站内路径（**去掉 query 中疑似敏感参数**：保留 `q/cat/page`，其余剥离）；
- **环境白名单**：浏览器 UA、屏幕尺寸、语言、时区；
- **不采集**：IP（不存）、Cookie、localStorage、任何用户输入过的内容、其它页面的历史记录。

这条边界写进「不适用条件」，实现时按白名单取，不做全量 `navigator` 转储。

## 7. 可见性与权限

### 7.1 三个可见层级（「公开」只指第三层）

| 层级 | 谁能看 | 内容范围 | 何时生效 |
|---|---|---|---|
| L1 本人 | 提交者自己 | 完整正文、截图、状态历史、管理员回复 | 提交即生效（**与「公开」无关**） |
| L2 管理员 | admin | 全部票（含所有人的） | 始终 |
| L3 全站 | 任何人（含未登录） | 只有管理员主动公开的条目：标题 + `public_summary` + 状态 + 修复时间；**不含**提交人、原始正文、截图、内部理由 | 管理员执行「公开」后出现在 `/known-issues` |

**要说清的一点**：提交者「能查看自己的反馈」是 L1，**从 P1 就有**，不需要任何公开动作；
本设计里的「公开」专指 **L3 全站可见**，且必须由管理员逐条主动发布——默认没有任何条目是公开的。

### 7.2 权限


| 动作 | 谁 |
|---|---|
| 提交 | 已登录且账号正常（`assertCanWrite`） |
| 查看自己的票 | 本人 |
| 查看全部 / 处理 / 公开 | 管理员（`assertCanAdmin`） |
| 公开页 | 所有人（无登录要求） |

### 7.3 通知

处理动作成功后给提交人投一条 `feedback_result`，正文 = 状态中文名 + `reply_text`（缺省用 `reason`），`link_url = /feedback/{id}`；
同一条处理记录只投一次（`notified` 字段 + 去重键 `feedback:{ticketId}:{recordId}`）。

## 8. 防滥用

- 限流：`rate_limits.feedback_per_hour`（默认 10/时/用户）；
- 去重：同用户 + 同 `kind` + 同 `page_url` 在 24h 内重复提交 → 直接返回已有票（幂等，不新建）；
- 长度闸：标题 120、正文 5000、公开发布摘要 500；
- 附件：≤3 张，只收 jpeg/png/webp，复用 media 的像素上限与 MIME 复核（不新写一份校验）；
- 全部走登录，天然排除匿名灌水；异常时可在后台把该用户 `disabled`（现有能力）。

## 9. 隐私与合规

- 票内容可能包含用户贴的截图（**可能含个人信息**）：默认私有，只有管理员可见；
- 公开页只显示管理员写的 `public_summary`，**不显示**提交人、原始正文、截图；
- `context_json` 只存白名单字段；不存 IP、不存精确地理位置；
- 通知里不发截图，只给链接；
- 管理员查看截图属于履职行为，写审计（谁在什么时候看了哪条票）。

## 10. 审计

| 动作名 | 触发 | actor |
|---|---|---|
| `feedback.create` | 提交 | user |
| `feedback.handle` | 任一处理动作（含理由） | admin |
| `feedback.publish` / `feedback.unpublish` | 公开/取消公开 | admin |

均写 `operation_records`（现有表），`target_type = feedback_ticket`。

## 12. 验收清单

| # | 场景 | 期望 |
|---|---|---|
| T1 | 未登录访问 `/feedback` | 跳登录（带 `returnTo`）；接口 401 |
| T2 | 提交 bug 票 | 落库 `open`，能在「我的反馈」看到 |
| T3 | 同页面 24h 内重复提交 | 返回已有票，不新建 |
| T4 | 超每小时上限 | 429（或 400 + 明确提示），不落库 |
