# 设计 · 讨论区（forum）与收藏体系重构

> 状态：设计已定，待实施
> 迁移：讨论区 0037；收藏重构 0038（0033–0036 已被精选与反馈占用）
> 拆分：PR A = 讨论区；PR B = 收藏重构（依赖 A 的帖子表）

## 1. 目标

站点目前只有「内容消费」：看评测、浏览插件、下载整合包。缺一个**用户之间对话**的场所。本设计补一个贴吧形态的讨论区，并把收藏从「插件独占」重做成三类内容共用的体系。

## 2. 范围

**做**

- 分区（board）：官方公告区默认存在；用户可申请新建分区；分区有区长
- 帖子（post）：Markdown + 图片；可编辑、可软删；可点赞、可收藏
- 回复（reply）：两层——顶层回复 + 对其的回复；Markdown + 图片（仅顶层）；顶层回复可点赞
- 分区权限：发帖策略（everyone / whitelist / admin_only）+ 黑名单；区长可删帖、置顶、任命协管
- 个人中心「我的帖子」：草稿 / 已发布
- 收藏重构：`/me/favorites/{plugins,packs,posts}` 三个子页，各自独立收藏夹

**不做**

- 回复的回复再往下嵌套（封顶两层）
- 帖子搜索、@提醒、私信
- 帖子进全站搜索（留待以后）
- 邮件/外发通知

## 3. 领域模型

### 3.1 分区

```
forum_boards
  id, slug(UNIQUE), name, description, posting_policy, is_official,
  status(active|archived), owner_id, created_at, updated_at

forum_board_moderators      -- 区长/协管（仅本分区生效）
  board_id, user_id, role(owner|moderator), granted_by, created_at
  PK(board_id, user_id)

forum_board_posting_rules   -- 白名单/黑名单
  board_id, user_id, mode(allow|deny), created_by, created_at
  PK(board_id, user_id)
```

`posting_policy` 三态：

| 值 | 含义 |
|---|---|
| `everyone` | 默认。所有登录用户可发，再被 `deny` 规则剔除 |
| `whitelist` | 只有 `allow` 名单内的人可发（区长与站方管理员始终可发） |
| `admin_only` | 仅站方管理员（官方公告区用） |

**判定顺序**：站方管理员 → 放行；分区 owner → 放行；命中 deny → 拒绝；`whitelist` 且不在 allow → 拒绝；`admin_only` → 拒绝；否则放行。

### 3.2 帖子与回复

```
forum_posts
  id, board_id, author_id, title(<=120), body_md(<=20000),
  status(published|deleted), deleted_by, deleted_at,
  is_pinned(0|1), like_count, reply_count, last_reply_at,
  created_at, updated_at, edited_at

forum_post_replies
  id, post_id, author_id, parent_id(NULL=顶层),
  body_md(<=10000), status(published|deleted),
  like_count, created_at, updated_at, edited_at

forum_post_likes          (post_id, user_id) PK
forum_post_reply_likes    (reply_id, user_id) PK
```

**两层约束由数据库兜底**：`parent_id` 指向的回复必须 `parent_id IS NULL`，用触发器保证——应用层写错也进不来。

**图片约束**：回复的回复（`parent_id IS NOT NULL`）不允许挂附件，用触发器保证。

**软删**：`status='deleted'`，行保留。列表显示「该帖已被作者删除」，回复者与收藏者能看到痕迹而不是内容凭空消失。

### 3.3 分区申请

```
forum_board_applications
  id, applicant_id, name, slug, description, reason(<=1000),
  status(pending|approved|rejected), reviewer_id, review_note, created_at, reviewed_at
```

通过时：建分区 → 申请人自动成为 `owner` → 写审计 → 站内通知申请人。

### 3.4 收藏重构

现状问题：`favorite_folders` 的默认夹约束是 `UNIQUE(user_id) WHERE is_default = 1`——每个用户全局只有一个默认夹。三类内容共用会出现「插件默认夹」和「帖子默认夹」打架。

```
favorite_folders
  + target_kind(plugin|pack|post)
  唯一索引改为 UNIQUE(user_id, target_kind) WHERE is_default = 1

pack_favorites   (user_id, pack_id, folder_id) -- 新建，从 plugin_pack_favorites 迁入
post_favorites   (user_id, post_id, folder_id) -- 新建
```

老数据迁移：现有 `favorite_folders` 全部标 `plugin`；`plugin_pack_favorites` 的收藏迁进新的 `pack_favorites` 并归入该用户的 pack 默认夹（迁移时创建）。

## 4. 页面

### 4.1 讨论区

| 路径 | 内容 |
|---|---|
| `/forum` | 分区列表 + 最新帖子 |
| `/forum/{slug}` | 分区内帖子列表，排序可切「最新发布 / 最后回复」，置顶优先 |
| `/forum/{slug}/{postId}` | 帖子详情 + 两层回复 |
| `/forum/new?board={slug}` | 发帖 |
| `/forum/{slug}/{postId}/edit` | 编辑（作者，或被授权的管理员/区长） |

### 4.2 后台

| 路径 | 内容 |
|---|---|
| `/admin/forum` | 分区列表、申请审核队列 |
| `/admin/forum/boards/{id}` | 分区设置：策略、白黑名单、区长任命 |

### 4.3 收藏

| 路径 | 内容 |
|---|---|
| `/me/favorites` | 重定向到 `/me/favorites/plugins` |
| `/me/favorites/plugins` | 插件收藏夹（沿用现有收藏夹） |
| `/me/favorites/packs` | 整合包收藏夹（新建） |
| `/me/favorites/posts` | 帖子收藏夹（新建） |

**旧链接兼容**：`/me/favorites/{folderId}` 现在指收藏夹详情，迁移后仍指向插件收藏夹详情（保留路径），不改。

## 5. 权限

| 动作 | 谁能做 |
|---|---|
| 发帖 | 按分区 `posting_policy` 判定 |
| 编辑帖子 | 作者；站方管理员；分区 owner |
| 软删帖子 | 作者；站方管理员；分区 owner / moderator |
| 置顶 | 分区 owner / moderator；站方管理员 |
| 任命/罢免协管 | 分区 owner；站方管理员 |
| 罢免 owner | **仅站方管理员** |
| 分区策略与白黑名单 | 分区 owner；站方管理员 |
| 审核分区申请 | 仅站方管理员 |
| 归档分区 | 仅站方管理员 |

**boundary**：owner 不能被自己任命的协管罢免——协管只能被 owner 或站方管理员罢免；owner 只能被站方管理员罢免。

## 6. 通知

新增 kind：
- `forum_reply`：有人回复了你的帖子
- `forum_reply_to_reply`：有人回复了你的回复
- `forum_board_application`：分区申请审核结果

去重键按「目标 + 事件」拼，避免同一动作重复轰炸。

## 7. 限流

`RATE_LIMIT_RULES` 新增：
- `forum_post`：每小时 10 帖
- `forum_reply`：每小时 30 条回复
- `forum_board_application`：每天 3 次

## 12. 已确认的决策

| # | 决策 |
|---|---|
| D1 | 回复两层封顶，回复的回复不能再往下 |
| D2 | 帖子与顶层回复用 Markdown 且可带图片；回复的回复不允许图片 |
| D3 | 帖子可编辑；删除是**软删**（使用者改口径，硬删会静默抹掉收藏者与回复者的痕迹） |
| D4 | 申请人自动成为分区 owner；管理员可指派其他人 |
| D5 | 区长权限：白黑名单、删帖、置顶、任命协管；**仅本分区生效** |
| D6 | owner 不可被协管罢免，只能被站方管理员罢免 |
| D7 | 策略 = `posting_policy` 三态 + 黑名单叠加，不是白/黑二选一 |
| D8 | 帖子列表排序可选「发布时间 / 最后回复时间」，**默认发布时间** |
| D9 | 分区支持归档 |
| D10 | 整合包收藏**也有**收藏夹（使用者第 9 条作答；与第 8 条的口误冲突，按第 9 条为准） |
| D11 | 拆两个 PR：A 讨论区、B 收藏重构；B 依赖 A |

## 13. 不适用条件

- 不替代已有的举报/纠错/申诉/反馈四条通道——讨论区是「用户之间说话」，不是「向站方报告问题」
- 不做无限层楼中楼（要改就得动回复树，现在是父子两层 + 触发器兜底）
- 不做帖子全文检索（本切片不建 `forum_post_search`）
