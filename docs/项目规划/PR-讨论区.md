## 功能

### 分区
- 首页 `/forum` 列出全部分区，显示发帖权限与帖数。
- 迁移自带两个默认分区：**官方公告**（`admin_only`，只有管理员能发）、**综合讨论**（`everyone`）。
  用 `WHERE EXISTS (SELECT 1 FROM users)` 守住，空库不建；`listBoards` 入口再调 `ensureDefaultBoards` 补建
  —— 这一步是跑 dev server 时发现的：空库访问分区列表直接 404，因为种子的调用点根本不存在。
- 发帖权限三态 `posting_policy`（`everyone` / `admin_only` / `whitelist`）+ **黑白名单叠加**，
  判定顺序固定：**归档 → 管理员 → 区长 → 黑名单 → admin_only → 白名单 → 放行**，**拒绝压过允许**。
  抽成纯函数 `decidePosting()`，服务层与页面读的是同一份规则。
- 分区可归档：归档后能看历史帖，不能发帖、不能回复。

### 区长与申请
- 用户可申请新建分区（填理由），管理员在 `/admin/forum` 审核。
- **申请人自动成为该区区长**；也可以由管理员指派别人。
- 区长权限只在自己那一区：管发帖权限、删帖、置顶、任命副区长。
- 区长不能被副区长撤，只有站方管理员能撤；区长不能撤自己（会留下无人管的区）。

### 帖子与回复
- 帖子与**顶层回复**用 Markdown，都可以带图。
- **回复的回复不能带图**——UI 不给入口，服务层也拒收，两层口径一致（触发器等在数据库）。
- 回复最多两层，第三层由迁移的触发器拒绝，服务层先给一句能看懂的话。
- 点赞：帖子可以，**顶层回复**可以，回复的回复不可以（迁移里有触发器保证）。
- 排序可选「最新发布 / 最后回复」，**默认最新发布**。
- 置顶帖恒定在列表顶部。

### 草稿
- `forum_post_drafts` **独立成表**，不塞进 `forum_posts`：草稿不需要置顶/计数/审核态，
  混进同一张表会让每条列表查询都得记得排除它，漏一处就把没写完的东西泄漏出去。
- 标题或正文为空都能存（写一半关页面是正常操作），**发布时才校验**。
- 发帖页支持 `?draft=` 续写，保存是覆盖式更新。
- **发布直接复用发帖那一个 `createPost`**：权限、归档判定、自动审核、附件规则都不另写一套，
  两条路径不可能漂移。发布成功删草稿，失败草稿原样留着。
- 「我的帖子」= 已发布 / 草稿 / 已删除三页。

### 自动审核
- 发帖时跑一组**本地纯函数规则**：空内容、外链过多（Markdown 图片不算）、违禁词、
  全大写标题、连续重复字符。
- 命中 → 压成 `pending_review`，不进公开列表；不命中 → 正常发布。两种都记一条 `forum_post_screenings`，
  后台能看到「这篇为什么进了人工」。
- 违禁词可配（站点设置 `forum.banned_words`，默认一套内置词），**报错文案里不回显命中的词**
  —— 否则等于告诉发帖人哪个词能钻空子。
- 与内容审核的差别是刻意的：内容审核在没配外部筛查供应商时停在人工（判不了「可疑」），
  讨论区规则是本地正则，判不了「可疑」但**判得了「明确命中」**，所以「没命中就放行」是有意义的。

### 举报
- `reports.target_kind` 扩展 `post` / `forum_reply`，帖子和每条顶层回复都有举报入口。
- 处理走既有流程（隐藏 / 驳回 / 要求举证），隐藏分支对讨论区目标是**软删**。

### 图片上传
- 先 `POST /api/forum/attachments` 登记，再 PUT 字节；就绪后把 Markdown 插进正文，
  **同时把 `attachmentId` 收进 `fileIds` 一起提交**——图不能只在正文里好看，也要真的算附件。
- 处理中/失败的图不算附件（引用了也打不开）。

## 顺带修掉的两个真 bug

这两个都是全量测试跑出来的，不是猜的：

1. **重建 `reports` 时把 `content_entity_id` 的 CHECK 写反了。**
   我写成「只有 review / pack_release 才非空」，但迁移 0012 规定**评论举报填所属内容实体**。
   结果所有评论举报都违反约束 —— `tests/interactions.test.ts` 当场报
   `CHECK constraint failed`。已按 0012 原口径改正。

2. **未处理举报的唯一索引漏了讨论区的目标列。**
   索引只按 `content_entity_id` 去重，而评论/帖子该列恒为 NULL，
   不同评论会被当成同一个目标互相挤占。已把 `comment_id` / `post_id` / `forum_reply_id` 并进索引键。

3. （测试自己抓到的顺序 bug）`removeModerator` 里「只有管理员能撤区长」的检查排在「不能撤自己」前面，
   导致区长撤自己返回的是 FORBIDDEN 而不是 INPUT_INVALID。已把自身检查提到最前。

## 已知取舍（请重点看这几条）

1. **发布时「发帖」与「删草稿」是两个请求，不在一个事务里。** 最坏情况是帖子发出去了但删草稿失败，
   留一条可手工删的草稿。反过来（一个事务）会因为删草稿失败把帖子一起回滚，用户以为发布失败
   却又占用了频控额度，更糟。
2. **讨论区关闭（`forum.enabled=false`）时页面与接口 404**，不是「无权限」。按站点的做法，
   未开放的功能对外表现为不存在。
3. **草稿列表不分页**，每人 100 条封顶。按实际操作频率判断，再多的草稿本身就是异常。
4. **回复的回复没有编辑/删除入口**——本 PR 只做了顶层回复的管理动作，这一层留到后续。
5. **区长的删帖是软删**，帖子行保留、`status='deleted'`；不级联删别人的回复与点赞，那是别人的痕迹。
6. 排序默认「最新发布」而不是「最后回复」——贴吧的习惯是后者，但按你说的默认前者；
   想改默认值只需动一处。
