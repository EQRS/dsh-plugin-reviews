### 迁移策略说明（**明确的偏离，需主人知悉**）

- 文档（架构 §6）要求用 **Drizzle-Kit 生成并执行有版本记录的 SQL 迁移**。
- 本切片采用**手写编号 SQL 迁移** + `schema_migrations` 版本表（`src/server/platform/migrate.ts`），
  同时保留 `drizzle-orm` 作为依赖用于查询层类型安全。
- 理由：本切片必须表达**延迟外键顺序、联合唯一、部分唯一索引、行内 CHECK 与跨行触发器**，
  这些是 Drizzle schema 生成器表达不稳或管不到的地方（也正是《设计评审意见》§8.3 点名的
  「手写迁移与 schema 定义不一致」风险区）。
- **权威结构是 `migrations/*.sql`**，不是 Drizzle schema。二者若不一致，以 SQL 为准。
- 影响：`drizzle-orm` 当前**只作为依赖存在**，未在业务代码中实际使用；这是一个已知的未收口项。

## 3.1 `dsh.bundle` 的真实形状（**勘误：曾按错的规格实现过**）

收录检查依赖"`package.json` 声明了 `dsh.bundle` 且引用的配置文件存在"。写这条规格时
曾把它当作**字符串**（`"dsh": { "bundle": "./cordis.patch.yml" }`），这是**错的**。

上游《打包与安装插件》给出的真实形状是**对象**，且 `patch` 可以是字符串**或有序数组**：

```json
{ "dsh": { "bundle": { "patch": "./cordis.patch.yml" } } }
```

真机复核（2026-10-11，`deepseek-ai/deepseek-harness` 的 `packages/bundle/base/package.json`）：

```
dsh = {"bundle":{"patch":"./cordis.patch.yml"}}
packages/bundle/base/cordis.patch.yml → HTTP 200
```

落地位置：`src/server/adapters/catalog/github-probe.ts`
（`extractBundlePatchPath` 同时接受对象与字符串形态；数组取**第一条**）。

| 项 | 结论 |
|---|---|
| 形状 | 对象 `{ bundle: { patch: string \| string[] } }` |
| 相对锚点 | 相对**声明它的 `package.json` 所在目录**（即 `pluginPath`），不是仓库根。依据：上游"每个文件中的相对插件路径相对**该文件**解析" |
| 数组语义 | 有序列表，按顺序作为同一层应用 ⇒ 完整核验需逐条检查 |
| 本切片收敛 | 契约 `CatalogProbe.fetchPluginManifest` 返回单个 `bundlePath`，故**只核验第一条**。对"引用文件是否存在"这项检查是**保守**的（不会因漏看后面几条而误放行）。**多 patch 完整核验需要扩契约，未做。** |

> 教训（值得留档）：这条规格是我写错的，实现者去查了上游文档才发现。
> 若实现者照抄任务描述，会写出一个**永远认为"没有 dsh.bundle"**的探针 ——
> 而单测若也按错的规格构造夹具，会一起绿着，把真实收录全部拒掉。
