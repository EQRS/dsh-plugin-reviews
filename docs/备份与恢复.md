# 备份与恢复

> 目标（`参数与管理规则.md §81`）：**每日 03:00（Asia/Shanghai）一个完整恢复点** + **管理员可立即备份**。
> 本文只描述线上真实做法，不含"计划中的能力"。

## 1. 备份里有什么

一份备份是一个目录，名字形如 `20261018-030000123-auto`（本地时间 + 毫秒 + 来源）：

| 文件 | 内容 |
|---|---|
| `app.sqlite` | 数据库副本。用 SQLite 的**在线热备 API**（`db.backup()`）生成，不是 `cp` —— WAL 下直接复制文件会漏掉未 checkpoint 的事务 |
| `media.tar.gz` | 媒体目录（原图/展示图）；没有媒体时不生成 |
| `manifest.json` | schema 版本、各表行数、`integrity_check` 结果、副本行数、sha256、耗时、来源路径 |

**生成后当场自检**：打开副本跑 `PRAGMA integrity_check`，并逐表比对行数与源库。
任何一项不合格，脚本退出码非 0（systemd 会把这次记成 failed，后台页面也会标红）——
不做校验的备份只能叫"以为有备份"。

## 2. 落在哪、留几份

```
/root/dsh-plugin-review/
├─ data/app.sqlite          ← 现役库
└─ backups/<时间戳>-<来源>/  ← 备份（默认保留 14 份，超出按时间删最旧）
```

备份目录**单独挂载**进 web 容器（`DSH_REVIEW_BACKUPS_DIR` → `/app/backups`），
与数据目录分开：数据出问题时，备份不会被同一个误操作一起带走。

> ⚠️ 同一台机器上的备份防的是**逻辑事故**（误删、迁移写坏、批量改错），
> **防不了整机/磁盘丢失**。异地副本仍需自己定期拉走，见 §6。

## 3. 每日自动备份

systemd 定时器（仓库 `deploy/` 下有同一份）：

```bash
install -m 644 deploy/dsh-review-backup.service /etc/systemd/system/
install -m 644 deploy/dsh-review-backup.timer   /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now dsh-review-backup.timer
systemctl list-timers dsh-review-backup.timer     # 看下次触发时间
```

* `OnCalendar=*-*-* 03:00:00`（服务器本地时区 Asia/Shanghai）+ `RandomizedDelaySec=5m`（避开同一秒的 IO 竞争）
* `Persistent=true`：关机/重启错过的那次，开机后补跑
* 实际执行：`docker compose run --rm --no-deps web node scripts/backup.mjs --label auto --keep 14`

## 4. 管理员立即备份

后台 → **存储与备份** → 「立即备份」（`POST /api/admin/backups`）。
它跑的是**同一个脚本**（`scripts/backup.mjs`），所以定时与手动不会有两套行为。

```bash
# 命令行等价物（排查时用）
cd /root/dsh-plugin-review/repo/docker
docker compose run --rm --no-deps web node scripts/backup.mjs --label manual --keep 14
```

## 5. 恢复（维护窗口操作）

```bash
# 1) 先看有哪些备份、并做一次"只验证不写"的演练
docker compose run --rm --no-deps web node scripts/restore-backup.mjs --latest --dry-run

# 2) 停服务（必须：SQLite 文件被进程打开时不能替换）
docker compose stop web worker

# 3) 真正恢复（现有库会被改名为 app.sqlite.before-restore-<时间戳>，不删）
docker compose run --rm --no-deps web node scripts/restore-backup.mjs --latest --force

# 4) 起服务并核对
docker compose start worker web
curl -s http://127.0.0.1/api/health     # schema_version 应与备份清单一致
```

脚本的顺序是**先验后写**：sha256 与清单不符 → 直接拒绝（不覆盖）；副本完整性不通过 → 拒绝；
只有都通过才落盘，并把旧库改名保留。媒体默认不动，需要一起回滚时加 `--media`。

## 6. 异地副本（仍需自己做）

同机备份不防整机丢失。建议每周把最新一份拉到本地或对象存储：

```bash
# 在本地机器上（示例）
scp -r root@5.231.26.36:/root/dsh-plugin-review/backups/$(ls -t ... | head -1) ./dsh-backup/
```

或接入任意支持 put 的对象存储。**这一步没有自动化** —— 如实说明，不假装已有。
