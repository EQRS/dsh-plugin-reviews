# 第一类收尾：参数与管理规则

状态：已确认；对应架构第 106 节，用户本轮同意继续。本文集中补齐剩余初始参数与管理边界，完整数据库模型见第二类提案 `数据库模型.md`。数值为本站启动参数，可调整，不代表容量实测结果。

## 1. 已确认参数

图片格式与限额、草稿自动保存、目录同步周期及不可访问判定沿用 `idea.md`；分页、任务并发与重试、执行权、处理超时、页面进度查询及登录时限沿用架构第 100—105 节。本文不重新选择这些参数。

## 2. 账户管理与主页公开

- 账户状态为 `active`、`disabled`，新用户默认正常。管理员通过用户管理页面禁用或恢复账户，必须填写原因，并提交当前管理版本及操作去重键。
- 用户增加 `management_version`，账户状态或角色实际变化时递增；个人昵称和头像修改不使用该管理版本。状态、必要会话撤销、版本和审计在同一短事务中更新。
- 禁用时撤销该用户现有会话，阻止新建登录会话和登录后操作；可以继续按匿名资格浏览公开内容。恢复后重新登录，原会话不恢复。
- 禁用不直接删除作者已公开内容、收藏或历史。违规内容由既定隐藏流程处理。账户状态切换与内容隐藏分别留痕。
- 未完成的该作者创作、导入及发布任务重新核验资格：账户禁用后停止新增创作及发布，失去资格的任务记为 `skipped`，对应未发布提交转为 `ineligible`，保留已有草稿、完整输入和历史。恢复账户不自动发布这些旧提交，作者按既定流程重新确认并提交新快照。
- 公共目录刷新、既有内容的通知及备份等系统职责按其实际业务资格继续，不仅依据任务发起人被禁用就清空任务。
- 状态或角色变更事务必须保证至少一个正常账户具有管理员角色，拒绝禁用或撤销最后一个有效管理员。后台展示账户状态、角色、原因与操作历史；普通页面不公开内部管理原因。
- `users.github_profile_visible_default` 建议为 `false`。首次资料确认提供公开 GitHub 主页选项，用户可修改；配置只影响新用户初始值，已有用户选择保留。该选项不承诺昵称或头像无法与 GitHub 资料关联。

## 3. 请求频控

| 配置键 | 首版建议值 |
|---|---|
| `rate_limits.comment_changes_per_minute` | 每用户每分钟最多 5 次新评论、回复或正文修改，合并计数。 |
| `rate_limits.plugin_submissions_per_hour` | 每用户每小时最多 10 次新的指定插件提交检查。 |

频控按服务端确认的站内用户、业务动作及滚动窗口计算。相同已成功请求键的重放返回原结果，不另算一次提交；窗口额度判定与实际接收新操作一起协调，不能靠多窗口绕过。无效输入有独立请求防护，不用业务计数冒充全部接口的流量控制。

超限返回明确等待信息，页面保留输入。评测批量投稿继续没有每小时篇数硬上限，整批由既定队列调度；插件目录的管理员批量导入及定时发现使用系统调度预算，不套用单个用户的十次提交限制。限额在后台可调整，不能通过只改前端参数放行。

## 4. 上传与导入接收

| 配置键 | 首版建议值 |
|---|---|
| `uploads.receive_lease_seconds` | 文件接收执行权有效期 300 秒。 |
| `uploads.renew_interval_seconds` | 活动传输最多每 30 秒续期一次，须有实际传输活动依据。 |
| `uploads.max_transfer_seconds` | 每次单文件完整传输最长 1,800 秒，续期不能突破。 |
| `imports.max_markdown_bytes` | 单个 Markdown 输入最多 2MB；图片继续沿用已确认限额。 |

以上用于第 71、73 节实际文件传输尝试，与后台任务执行权分开。续期间隔不超过接收执行权的四分之一，总传输期限不得小于接收执行权；接收进程、尝试标识及未过期条件同时核验。连接中断或期限失效后按原整文件重传规则恢复，完整已接收输入不重复上传。

Markdown 超限逐项显示原因，其他合格输入照常处理；批次不因一项失败整体撤销。单篇图片数量、封面计数及图片真实格式校验继续沿用已确认规则，上传声明大小不代替实际字节核验。

## 5. 外部读取与安装核验

| 配置键 | 首版建议值 |
|---|---|
| `github.requests_per_minute` | 所有 GitHub API 请求合计最多 30 次／分钟，保持已确认串行发送。 |
| `github.search_requests_per_minute` | 仓库搜索最多 20 次／分钟，同时计入上述合计。 |
| `github.interactive_budget_reserve_ratio` | 将各资源窗口可用预算的 20% 预留给用户指定检查，后台批量刷新在该保留线前暂停；窗口预算同时受响应头约束。 |
| `github.mutable_cache_seconds` | 可变公开资料缓存有效期 900 秒。 |
| `github.commit_cache_seconds` | 确定提交下的公开文件缓存有效期 604,800 秒。 |
| `catalog.install_check_validity_seconds` | 对匹配目标及依据指纹的成功核验，当前有效期 86,400 秒。 |
| `external_reads.max_response_bytes` | 普通结构化来源响应最多 10MB，包括目录清单和文件树。 |
| `external_reads.max_readme_bytes` | 单份 README 最多 2MB。 |
| `external_reads.max_package_archive_bytes` | 安装资料核验的单份发布包最多 50MB。 |
| `external_reads.max_package_entries` | 单份发布包最多检查 2,000 个清单项，超过范围保留未完成结果。 |
| `catalog.scan.max_requests_per_repository` | 一轮单仓库自动目录扫描最多 50 次实际请求，达到后标记未完成，可用明确子目录继续检查。 |

这些是本站保守预算，不是 GitHub 授予的额度；第 96 节响应限额、资源冷却和二次限流要求优先。管理员及用户指定检查均不能突破上游等待。缓存命中不冒充本轮有效检查，明确重新检查可绕过可变资料的新鲜缓存，但仍遵守预算。

缓存有效期控制复用资格，过期不等于删除历史输入；匹配完整缓存仍可用于条件重新确认。成功安装核验过期后显示需复查，来源变化和目标变化立即失去匹配资格；待核验目标不生成本站安装命令，发起受控核验成功后恢复。故障保留原依据及时间，不判断为目标失效。

首版重查沿用每日同步、用户指定检查及既定业务核验，不另增逐用户提醒或后台高频扫描。超出读取限制显示真实原因及未完成范围，不拿受限结果清空资料或撤回来源；不执行包内代码，不将包路径写入任意服务器位置。具体读取操作仍服从第 103 节超时。

## 6. 搜索权重与预览数量

| 配置键 | 首版建议值 |
|---|---|
| `search.plugin_field_weights` | 名称 4、仓库 3、所有者 2、简介 1。 |
| `search.review_field_weights` | 标题 4、关联插件名称 2、正文 1。 |
| `search.pack_field_weights` | 名称 4、用途说明 1。 |
| `home.latest_review_count` | 首页最新评测 6 条。 |
| `home.recent_plugin_count` | 首页近期更新插件 12 条。 |
| `comments.reply_preview_count` | 每讨论组预览最多 3 条公开回复，按已确认回复顺序读取，完整回复继续单独分页。 |

权重是受限字段的相对参数，搜索模块按已确认检索方案使用；长词与短词路径共同核验可见性、条件及稳定次序，排序参数不变成额外公开评分。零结果、已隐藏或已撤回内容不会为了凑预览数量出现。非关键词列表继续使用各自既定排序，不按这些权重替代发布时间排序。

## 7. 备份、保留与清理边界

- `backups.schedule_timezone` 建议为 `Asia/Shanghai`，`backups.daily_time` 为 `03:00`，每日安排一次完整恢复点；管理员可立即备份。安排、去重与错过周期恢复沿用持久调度规则，时间保存使用既定 UTC 毫秒。
- 首版保留方式为 `keep_all`：完整恢复点、历史快照、审计、发现依据及操作回执全部保留，后台展示数量和占用。首版不提供内容永久删除、自动回执过期清理或自动物理文件清理；这些作为后续独立策略设计，不把没有处理逻辑的清理开关放入设置界面。
- 未完整传输的尝试可以按既定期限结束，结束不等于立即删除暂存文件。历史、任务和备份仍引用的输入受原保护规则约束，本文不授权执行任何现实数据删除。
- 备份文件完整性和独立位置副本状态分别展示，失败备份不冒充可恢复结果；独立存储位置和提供商在部署类别落实。本类别决定周期及首版保留边界，不代表已经具备实际恢复能力。

## 8. 配置与实现交接

新增参数均通过已注册定义提供类型、允许范围、权限、生效时点与管理表单。并发、时长、字节数和数量为有界正值，权重为正值，预算保留比例大于等于零且小于一；相关值一起校验。初始建议不作为适用于所有硬件和外部提供商的固定容量。

普通配置下一次操作采用新版本，执行中的尝试保留快照，既有用户的公开选择及会话最终期限继续按原规则处理。秘密配置、存储地址迁移、身份角色、账户状态及内容控制仍使用对应专门业务流程。

第二类完整模型中落实这些注册项的具体校验值域、账户管理版本、频控事实记录、传输截止时间及对应索引；对实现依赖产生的必要调整另行标明，不静默改变已确认业务。本文记录已确认设计，未新增实际账户、备份任务或清理任务。
