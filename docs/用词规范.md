# 用词规范（测评文字照此写）

> 适用：站内测评正文、插件简介、结论速览、表格、评论回复、给作者的反馈。
> 不适用：代码、命令输出、录屏里用户的原话、内部工作笔记。
>
> 检查方式：`pnpm check:wording`（默认扫 `docs/`）；命中 `error` 即退出码 1。
> 本页的禁用词都放在行内代码里，既是示例，也避免被自己的检查扫到。

## 一、五条规则

| 规则 | 意思 | 怎么判 |
|---|---|---|
| 1 用初中词汇 | 用初中生看得懂的词 | 换掉一个词，意思不变，就换 |
| 2 一句说一件事 | 一句话只讲一件事 | 超过 30 字就拆开 |
| 3 不用英文 | 除例外五项，一律中文 | 见第三节 |
| 4 不用专有词 | 不用行业黑话 | 见第二节替换表 |
| 5 不堆修饰词 | 不写程度、肯定、夸张、语气、推测、方式类状语补语 | 见第四节 |

## 三、英文处理

**可以用（例外）**：

1. 插件名：`dsh-memory`、`meow-memory`
2. 版本号：`0.9.8`、`v0.9.6`
3. 命令与路径：`dsh plugin --profile web add ...`
4. 被测对象的名字：DSH、DeepSeek
5. 网址：review.lingshulab.com（链接要点得开）

**不能用，一律换中文**：

| 禁用 | 改成 |
|---|---|
| `Node` | 运行环境 |
| `npm` | 安装工具 |
| `API` | 网页接口 |
| `HTTP` | 网页请求 |
| `SQLite` | 本地数据库 |
| `MIT` / `BSD` / `Apache` | 开源许可 |
| `beta` / `rc` | 测试版 |
| `issue` | 问题 |
| `tag` / `commit` / `release` | 版本标记、提交记录、发布页 |
| `profile` | 配置 |
| `demo` | 演示 |
| `star` | 星 |

## 四、禁用的修饰词

**程度类**：`非常`、`十分`、`极其`、`特别`、`相当`、`比较`、`挺`、`蛮`、`太`、`很`、`更`、`尤其`、`格外`
**肯定强调类**：`真的`、`确实`、`实在`、`的确`、`明明`
**夸张类**：`大幅`、`显著`、`明显`、`彻底`、`完全`、`全部`、`所有`、`几乎`、`基本上`
**语气类**：`其实`、`竟然`、`居然`、`简直`、`反倒`、`反而`
**推测类**：`大概`、`可能`、`也许`、`似乎`、`好像`、`恐怕`
**方式类**：`好好地`、`牢牢`、`狠狠地`、`慢慢地`、`快速地`、`仔细地`、`认真地`

一个例外：**「最」在客观比较里可以用，在评价里不能用。**

- ✅ 「星最多」「要顺带装的东西最多」「版本最高」—— 比的是数
- ❌ 「最好用」「最强」—— 给的是评价（标题除外，标题是作者定的）

**怎么改**：

| 原句 | 改成 |
|---|---|
| 装得明显快 | 装它用 20 秒，装上一个用 4 分钟 |
| 这个插件确实有用 | 装它做 24 次，24 次全对；不装做 24 次，0 次对 |
| 其实它不记偏好 | 它只记项目，不记偏好 |

## 五、正反例

| 反面 | 正面 |
|---|---|
| 它是唯一有公开标准测评判定的 | 十个插件里，只有它有一份公开报告，报告写的是「有用」 |
| 不装的那一组连工具都不存在 | 不装的那一组，写的时候报「找不到工具」 |
| 有 27 个依赖，是最重的 | 装它要顺带装 27 个东西 |
| 引擎区间是硬闸门 | 你的 DSH 版本不在它写的范围里，它就装不上 |
| 主动注入等于吃对话内容 | 它每次都把记忆塞进对话，占地方 |

## 六、发布前自查

- [ ] 通读一遍，有没有一个初中生看不懂的词
- [ ] 搜一遍英文字母，除例外五项外还有没有
- [ ] 搜第四节禁用词，命中即改
- [ ] 每句是不是只说了一件事
- [ ] 跑一遍 `pnpm check:wording`，error 清零

## 七、检查脚本

`scripts/check-wording.mjs` 把第二、三节做成 `error`，第四节做成 `warning`。

```bash
node scripts/check-wording.mjs docs/用词规范.md      # 指明要查的文件或目录
node scripts/check-wording.mjs assessment/2026-10.md # 一篇测评正文
node scripts/check-wording.mjs --strict docs/x.md    # warning 也算失败
```

**只对「对外文字」生效，不扫技术文档。** 接口清单、部署说明这类内部文档里 API、HTTP、本地数据库都是准确说法，不该改；
如果确实要一起查，加 `--force` 或在文件里写 `<!-- wording-allow-file -->` 整篇跳过。

不查的地方：代码块、行内代码、网址、插件名、版本号、命令、被测对象名。
单字「很」「更」「太」「挺」「蛮」不查，因为「更新」「更多」不是程度状语。
