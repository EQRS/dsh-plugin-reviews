# 分类与标签（用途分类）

> 一句话：**GitHub topics 是原料，`plugin_categories` 是口径**。
> 页面上看到的「用途分类」来自后者；前者只在插件详情页作为小字展示。

## 1. 两层模型

```
GitHub 仓库 topics（仓库级、英文、由作者自己打）
        │  收录/刷新时抓取（acceptPluginSubmission）
        ▼
repositories.topics        JSON 数组文本，原样保存（小写、去重、≤64 字符、最多 50 个）
        │
        │  分类认领：plugin_categories.topics ∩ repositories.topics ≠ ∅
        ▼
用途分类（plugin_categories）  中文名 + 排序 + 是否显示；**页面 chip 行与左栏筛选只认这一层**
```

## 2. 为什么要这一层（三个线上实测的问题）

| 问题 | 证据 | 分类这一层怎么解决 |
|---|---|---|
| 自指标签没有区分度 | 50 个插件里 `dsh-plugin` 覆盖 46 个、`deepseek-harness` 40 个 | 这两个 topic **不被任何分类认领**，因此不会出现在 chip 行 |
| monorepo 把计数放大 | `hyzyn/dsh-plugin-kit` 一个仓库 11 个 packages，让 `docker`/`rss`/`ftp`/`ssh` 各 +11 | chip 计数改成 **distinct repository**（覆盖多少个仓库），line 里同时保留插件数供后台看 |
| 标签是英文原样、没有中文口径 | 左栏一度是 `dsh-plugin 46`、`agentic-os 2` | 分类带中文 `label`，一个分类认领多个英文 topic |

## 3. 数据表（迁移 `0010_plugin_categories.sql`）

```sql
plugin_categories(
  slug        TEXT PRIMARY KEY,   -- URL 里用：/plugins?cat=memory
  label       TEXT NOT NULL,      -- 中文展示名（≤20 字，**全表唯一**）
  topics      TEXT NOT NULL,      -- JSON 数组，认领的 GitHub topics（小写，1–50 个）
  sort_order  INTEGER,            -- 越小越靠前
  is_visible  INTEGER,            -- 0 = 不参与筛选、不进 chip 行（但后台可见）
  created_at, updated_at
)
```

种子数据在迁移里（10 个分类：记忆与知识 / 搜索与检索 / 多智能体 / 安全与护栏 / 工具与终端 /
数据与存储 / 代码与编程 / 媒体与内容 / 集成与协议 / 界面与交互）。

**「未分类」不落表**：它是"插件所在仓库的 topics 一个分类都没命中"算出来的（`__none__`）。
注意与 `repositories.topics IS NULL`（`UNCLASSIFIED_TAG`）区分：前者要运营补映射，后者是抓取缺失。

## 4. 维护方式

后台 → **分类管理**（`/admin`，管理员）：

* 已有分类：改名称 / 认领的 topics / 排序 / 是否显示 / 删除；
* **待归类 topics**：按"覆盖多少不同仓库"列出所有没被认领的 topic，点一下即可加进草稿 —— 
  分类应当从真实数据里长出来，而不是凭空设计十个盒子；
* 校验（服务端 fail-closed）：slug `^[a-z0-9][a-z0-9-]{1,31}$`、label 1–20 字且不重名、
  topics 必须是小写合法 topic 且 ≥1 个、排序 0–9999；非管理员 403。

```bash
# 命令行看当前分类与覆盖率（只读）
curl -s https://review.lingshulab.com/api/plugins?page_size=50 | \
  python3 -c "import sys,json;[print(p['displayName'] or p['repositoryFullName'], p['categories'], p['topics']) for p in json.load(sys.stdin)['data']['items'][:5]]"
```

## 5. 口径边界（如实说明）

* 分类是**仓库级**的：同一仓库的多个 packages 共享同一组分类。想做"插件级分类"必须让作者
  在 `package.json` 里声明，或人工逐条指定 —— 当前切片不做。
* topics 只在**重新收录检查**时刷新（发现器 `refreshed` 或用户重新提交），没有独立轮询；
  作者改了 topics，页面上要等下一次探测。
* 一个 topic 被多个分类认领时，插件会同时出现在多个分类里（计数各自 +1），这是有意的：
  分类是多对多的视图，不是互斥分区。
