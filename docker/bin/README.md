# docker/bin —— 随镜像携带的二进制附加物

## 这里放什么

只有**必须随镜像走、又无法在构建阶段从包管理器拿到**的二进制文件，例如：

- 预编译好的原生附加模块（`.node`），用于目标平台没有预编译包、又不想在构建里现编译的场景；
- 离线场景用的初始数据（例如一个已经跑完迁移的空库 `seed.sqlite`）；
- 需要在容器内执行的一次性小工具（静态编译的单个可执行文件）。

## 这里不放什么

| 不放 | 为什么 | 正确做法 |
|---|---|---|
| 证书 / 私钥 | 不该进镜像，也不该进 git | 挂载 `${DSH_REVIEW_ROOT}/certs`（见 docker/compose.yaml） |
| 数据库、媒体图片 | 是运行期数据，属于宿主 `/root` 下的数据目录 | bind mount 到 `/app/.data` |
| `node_modules`、`.next` | 由镜像构建阶段生成 | `docker compose build` |
| 密钥、`.env` | 秘密一律运行时注入 | `docker/.env`（chmod 600，不进 git） |
| 大体积发行版（JDK/Python 之类） | 镜像该由基础镜像提供 | 换基础镜像或在 Dockerfile 里 `apk/apt` 安装 |

## 怎么被使用

镜像构建时执行 `COPY docker/bin ./bin`，内容出现在容器内 `/app/bin`。

目录为空时只是建一个空的 `/app/bin`，不影响构建；`.keep` 只是为了确保目录存在于 git 与构建上下文里。

## 注意

放进这里的东西会成为**镜像的一部分**（每次构建都要重新 COPY），
所以它能被 `docker history` / 镜像层看到 —— 不要放任何敏感内容。
